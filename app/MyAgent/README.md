## Laravel customer search tool

The code added for this integration is surrounded by comments containing
`Laravel customer search tool implementation: START` and `END`.

- `laravel_tools/customer_search.py`: validates tool parameters, reads the
  Sanctum token from Strands ToolContext, calls Laravel, and filters returned fields.
- `agent/tool_registry.py`: explicitly lists the tools made available to the agent.
- `invocation/request_parser.py`: validates the Laravel authentication values
  before they are passed to Strands as invocation state.
- `agentcore/agentcore.json`: supplies the Laravel endpoint URL to the runtime.

Laravel sends `authenticated_user_id` and `user_access_token` in the Runtime
payload. `main.py` validates them and passes them to Strands as invocation state.
The token is not exposed as a model-controlled tool argument. The customer tool
sends it to Laravel using the `Authorization: Bearer ...` header, where
`auth:sanctum` resolves the user and checks the token ability.

The current endpoint uses plain HTTP and must therefore be used only with dummy
data during this proof of concept. Move it to HTTPS before sending real customer
data or using it in production.

## Browser lifecycle

`agent/factory.py` creates a new `AgentCoreBrowser` for every Runtime invocation.
Browser instances must not be shared across requests because the Browser `close`
action stops its Playwright instance and that same object cannot initialize
another session. Each invocation also receives a unique browser session name in
its system prompt to prevent collisions with sessions from earlier requests. The
name is kept within the Browser API's 36-character limit.

`browser_tools/reliable_agentcore_browser.py` bounds navigation to 20 seconds
and waits for `domcontentloaded` instead of `networkidle`. This prevents search
pages with continuous background requests from blocking the whole invocation.

## Application structure

The application uses a small feature-based structure. Start with `main.py` to
follow the Runtime request flow, then open the feature folder for its details.

- `main.py`: AgentCore entrypoint and the explicit memory/no-memory branch.
- `agent/factory.py`: creates the model, Browser, tools, prompt, and Strands Agent.
- `agent/prompts.py`: contains the base and per-browser-session system prompts.
- `agent/tool_registry.py`: lists every non-browser tool available to the model.
- `invocation/request_parser.py`: validates auth, memory, text, and image payloads.
- `invocation/streaming.py`: filters and yields Strands streaming events.
- `browser_tools/`: contains Playwright setup and Browser reliability changes.
- `laravel_tools/`: contains tools that call the Laravel application.
- `memory/`: contains AgentCore Memory session configuration.
- `mcp_client/`: contains the optional AgentCore Gateway MCP client.
- `model/`: contains Bedrock model configuration.

## Conversation memory

Memory is disabled unless the request explicitly contains both
`"use_memory": true` and an `actor_id`.

The runtime session ID is used as the AgentCore Memory `session_id`. Reuse the
same runtime session ID for every turn in one conversation. Start a new runtime
session ID for a new conversation.

Example payload:

```json
{
  "prompt": "前に話した内容を覚えていますか？",
  "use_memory": true,
  "actor_id": "user-123"
}
```

The caller must derive `actor_id` from the authenticated user. Do not accept an
arbitrary actor ID supplied by browser JavaScript.

For a no-memory request, omit `use_memory` and `actor_id`:

```json
{
  "prompt": "この質問だけに回答してください"
}
```

# Developing locally

If installation was successful, a virtual environment is already created with dependencies installed.

Activate the environment with `source .venv/bin/activate` on macOS/Linux, `.venv\Scripts\activate.bat` in Windows
Command Prompt, or `.\.venv\Scripts\activate.ps1` in Windows PowerShell.

`agentcore dev` will start a local server on 0.0.0.0:8080.

In a new terminal, you can invoke that server with:

`agentcore invoke --dev "What can you do"`
